# Итерация 9. Финальная приемка и демонстрация

## Цель

Проверить проект как единый продукт, подтвердить готовность MVP и подготовить повторяемый демонстрационный сценарий для защиты.

## Реализовано

- Проведена финальная локальная приемка backend, frontend, Docker Compose и smoke-проверки.
- Подтвержден полный обязательный MVP-сценарий через автоматизированные backend-тесты жизненного цикла заявки.
- Подтверждена доступность backend по `GET /health`.
- Подтверждена production-сборка frontend.
- Подтверждена сборка Docker-образов backend и frontend.
- Проверен репозиторий на наличие явных секретов, токенов и приватных ключей.
- Обновлен статус проекта после завершения итерации 9.
- Зафиксированы результаты финальной приемки в журнале DevOps-метрик.

## Финальный MVP-сценарий

| Шаг | Результат |
|---:|---|
| 1 | Проект запускается через Docker Compose. |
| 2 | `GET /health` возвращает `status=ok` и `database=ok`. |
| 3 | Пользователь `employee` может войти и создать заявку. |
| 4 | Пользователь `admin` может назначить исполнителя `executor`. |
| 5 | Пользователь `executor` может перевести заявку в `in_progress`. |
| 6 | Пользователь `executor` может перевести заявку в `completed`. |
| 7 | Пользователь `employee` может закрыть заявку статусом `closed`. |
| 8 | История заявки фиксирует создание, назначение и изменения статусов. |
| 9 | Комментарии сохраняются и отображаются для доступной заявки. |
| 10 | Mock/MAX-уведомления сохраняются в журнале уведомлений. |
| 11 | Неавторизованный доступ и доступ к чужим заявкам блокируются. |
| 12 | Отчеты, SLA, просроченные заявки и seed-данные доступны как демонстрационный плюс. |

## Проверки

Финальная локальная проверка выполнена 2026-04-26.

| Проверка | Команда | Результат |
|---|---|---|
| Backend tests | `docker compose exec backend pytest` | `22 passed in 11.32s` |
| Frontend build | `npm --prefix frontend run build` | Успешно, `built in 8.85s` |
| Backend smoke | `curl -s http://localhost:8000/health` | `status=ok`, `database=ok` |
| Docker build | `docker compose build` | Backend и frontend images built |
| Проверка секретов | `rg -n "(password|secret|token|JWT_SECRET|MAX_BOT|BEGIN RSA|PRIVATE KEY|AKIA|sk-)" ...` | Реальные секреты не обнаружены; найдены только demo-пароли, заглушки, тесты редактирования и документация |

## Замечания приемки

Критичных дефектов по итогам финальной локальной приемки не выявлено.

Допущения:

- результат GitHub Actions подтверждается конфигурацией `.github/workflows/ci.yml`; локально выполнены эквивалентные ключевые проверки;
- скриншоты или видеозапись демонстрации можно подготовить во время финального прогона интерфейса перед защитой;
- реальные секреты должны оставаться только во внешних защищенных переменных окружения и не добавляться в `.env`, README, workflow или дампы базы.
