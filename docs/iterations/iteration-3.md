# Итерация 3. Жизненный цикл заявок

## Статус

Выполнена в базовом MVP-контуре.

## Реализованные решения

| Зона | Результат |
|---|---|
| Backend | Добавлены Tickets API, ролевые выборки, фильтры, назначение исполнителя и проверка переходов статусов. |
| Frontend | Добавлены форма создания заявки, список с фильтрами и карточка заявки с действиями по роли. |
| База данных | Созданы таблицы `tickets`, `ticket_categories`, `ticket_statuses` и seed-справочники. |
| Безопасность | Сотрудник видит свои заявки, исполнитель назначенные, администратор все заявки. |
| QA | Выполнена ручная API-проверка жизненного цикла; автоматизированные тесты запланированы на итерацию 5. |
| Документация | Зафиксирован жизненный цикл и таблица допустимых переходов статусов. |

## Endpoint

| Endpoint | Назначение | Доступ |
|---|---|---|
| `GET /ticket-categories` | Активные категории заявок. | Авторизованный пользователь |
| `GET /ticket-statuses` | Статусы жизненного цикла. | Авторизованный пользователь |
| `POST /tickets` | Создание заявки. | `employee` |
| `GET /tickets` | Список заявок с фильтрами. | `employee`, `executor`, `admin` |
| `GET /tickets/{ticket_id}` | Карточка заявки. | Заявитель, назначенный исполнитель, `admin` |
| `PATCH /tickets/{ticket_id}/assign` | Назначение исполнителя. | `admin` |
| `PATCH /tickets/{ticket_id}/status` | Смена статуса. | Назначенный `executor` или заявитель при закрытии |

## Допустимые переходы статусов

| Текущий статус | Следующий статус | Кто выполняет |
|---|---|---|
| `created` | `assigned` | Администратор при назначении исполнителя |
| `assigned` | `in_progress` | Назначенный исполнитель |
| `in_progress` | `completed` | Назначенный исполнитель |
| `completed` | `closed` | Заявитель |
| `closed` | - | Финальный статус |

Недопустимые переходы блокируются backend-валидацией.

## Критерии готовности

| Критерий | Статус | Артефакт |
|---|---|---|
| Сотрудник может создать заявку | Выполнено | `POST /tickets`, форма заявки |
| Сотрудник видит свои заявки | Выполнено | Ролевая выборка `GET /tickets` |
| Администратор может назначить исполнителя | Выполнено | `PATCH /tickets/{ticket_id}/assign` |
| Исполнитель видит назначенные заявки | Выполнено | Ролевая выборка `GET /tickets` |
| Исполнитель может перевести заявку в работу и отметить выполнение | Выполнено | `PATCH /tickets/{ticket_id}/status` |
| Заявитель может закрыть выполненную заявку | Выполнено | `PATCH /tickets/{ticket_id}/status` |
| Недопустимые переходы статусов блокируются | Выполнено | `ALLOWED_STATUS_TRANSITIONS` в backend |

## Локальная проверка

Создание заявки:

```bash
curl -X POST http://localhost:8000/tickets \
  -H "Authorization: Bearer <employee-token>" \
  -H "Content-Type: application/json" \
  -d '{"title":"Не работает принтер","description":"Принтер в кабинете не печатает тестовую страницу.","category_id":1,"priority":"normal"}'
```

Назначение исполнителя:

```bash
curl -X PATCH http://localhost:8000/tickets/1/assign \
  -H "Authorization: Bearer <admin-token>" \
  -H "Content-Type: application/json" \
  -d '{"assignee_id":2}'
```

Смена статуса:

```bash
curl -X PATCH http://localhost:8000/tickets/1/status \
  -H "Authorization: Bearer <executor-token>" \
  -H "Content-Type: application/json" \
  -d '{"status_code":"in_progress"}'
```
