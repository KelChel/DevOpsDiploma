# Итерация 4. История, комментарии и уведомления

## Статус

Выполнена в MVP-контуре.

## Реализованные решения

| Зона | Результат |
|---|---|
| Backend | Добавлены история изменений, комментарии, журнал уведомлений и `NotificationProvider`. |
| Frontend | В карточке заявки добавлены ленты комментариев, истории и уведомлений. |
| База данных | Созданы таблицы `ticket_history`, `ticket_comments`, `notification_logs`. |
| DevOps | Провайдер уведомлений выбирается через `NOTIFICATION_PROVIDER`; параметры MAX вынесены в переменные окружения. |
| Безопасность | Реальные токены MAX не хранятся в коде; доступ к истории и комментариям ограничен участниками заявки и администратором. |
| QA | Базовая автоматизация вынесена в итерацию 5, для текущей итерации подготовлены проверяемые endpoint. |

## Endpoint

| Endpoint | Назначение | Доступ |
|---|---|---|
| `GET /tickets/{ticket_id}/history` | История ключевых событий заявки. | Заявитель, назначенный исполнитель, `admin` |
| `GET /tickets/{ticket_id}/comments` | Комментарии по заявке. | Заявитель, назначенный исполнитель, `admin` |
| `POST /tickets/{ticket_id}/comments` | Добавление комментария. | Заявитель, назначенный исполнитель, `admin` |
| `GET /tickets/{ticket_id}/notifications` | Журнал уведомлений по заявке. | Заявитель, назначенный исполнитель, `admin` |

## События истории

| Событие | Когда создается |
|---|---|
| `ticket_created` | При создании заявки сотрудником. |
| `ticket_assigned` | При назначении или переназначении исполнителя администратором. |
| `status_changed` | При допустимой смене статуса. |
| `comment_added` | При добавлении комментария. |

## Уведомления

Интерфейс `NotificationProvider` реализован в `backend/app/notifications.py`.

Поддержаны два режима:

| Провайдер | Поведение |
|---|---|
| `mock` | Считает отправку успешной и сохраняет запись со статусом `sent`. |
| `max` | Подготовлен как заменяемый адаптер. Если `MAX_API_BASE_URL` или `MAX_BOT_TOKEN` не заданы, сохраняет статус `failed` без сетевой отправки. |

Результат каждой попытки сохраняется в `notification_logs`: событие, провайдер, получатель, статус, время и текст ошибки при неуспехе.

## Критерии готовности

| Критерий | Статус | Артефакт |
|---|---|---|
| История показывает ключевые изменения заявки | Выполнено | `ticket_history`, `GET /tickets/{id}/history` |
| Комментарии сохраняются и отображаются | Выполнено | `ticket_comments`, UI в карточке заявки |
| При создании, назначении, изменении статуса и комментарии создается уведомление | Выполнено | `_log_notifications` |
| Mock-провайдер сохраняет статус, время и ошибку при неуспехе | Выполнено | `notification_logs`, `MockNotificationProvider`, `MaxNotificationProvider` |
| Реальные токены MAX не хранятся в коде и репозитории | Выполнено | `.env.example`, `Settings` |

## Локальная проверка

Добавление комментария:

```bash
curl -X POST http://localhost:8000/tickets/1/comments \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"body":"Принято в работу, проверяем оборудование."}'
```

Просмотр истории:

```bash
curl http://localhost:8000/tickets/1/history \
  -H "Authorization: Bearer <token>"
```

Просмотр уведомлений:

```bash
curl http://localhost:8000/tickets/1/notifications \
  -H "Authorization: Bearer <token>"
```
