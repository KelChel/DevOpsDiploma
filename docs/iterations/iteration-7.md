# Итерация 7. Отчеты, SLA и демонстрационный плюс

## Цель

Добавить управленческую ценность к MVP: расчет SLA, видимость просрочек, сводные отчеты и демонстрационные данные для защиты.

## Реализовано

- Добавлено поле `tickets.sla_due_at` и индекс `ix_tickets_sla_due_at`.
- Реализован расчет SLA при создании заявки по приоритету:
  - `critical` - 4 часа;
  - `high` - 24 часа;
  - `normal` - 48 часов;
  - `low` - 72 часа.
- API заявки возвращает `sla_due_at` и вычисляемый признак `is_overdue`.
- Добавлен endpoint `GET /reports/summary` для ролей `admin` и `manager`.
- Отчет содержит общее число заявок, открытые, закрытые, просроченные, распределение по статусам и категориям, нагрузку исполнителей и список просроченных заявок.
- Frontend показывает SLA в списке и карточке заявки.
- Просроченные заявки выделяются отдельным признаком.
- Добавлена панель отчетов для администратора и руководителя.
- Подготовлены демонстрационные seed-заявки для отчетов и SLA.
- Добавлены API-тесты SLA и отчетов.

## API отчетов

`GET /reports/summary`

Параметры:

| Параметр | Назначение |
|---|---|
| `date_from` | Начало периода по дате создания заявки. |
| `date_to` | Конец периода по дате создания заявки. |

Доступ: `admin`, `manager`.

## Критерии готовности

- Срок SLA рассчитывается при создании заявки.
- API возвращает признак просрочки.
- Руководитель и администратор получают отчетную сводку.
- Интерфейс показывает статистику и список просроченных заявок.
- Seed-данные позволяют быстро показать отчет без ручного наполнения базы.
- Backend-тесты проходят успешно.
