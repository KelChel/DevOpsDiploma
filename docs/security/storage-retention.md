# Учебное хранение данных и очистка

## Режим хранения

Проект использует учебную PostgreSQL-базу, запущенную через Docker Compose. Данные предназначены для локальной разработки, тестирования и демонстрации магистерской работы.

Система не предназначена для промышленной эксплуатации и не хранит:

- медицинские данные пациентов;
- персональные данные пациентов;
- вложения;
- реальные токены и секреты;
- production-дампы.

## Очистка демонстрационной базы

Для полного сброса локальной демонстрационной базы можно остановить контейнеры и удалить volume:

```bash
docker compose down --volumes --remove-orphans
docker compose up --build
```

После повторного запуска миграции создают справочники, тестовых пользователей и демонстрационные заявки.

## Резервные копии

В учебном режиме резервные копии не являются частью MVP. Если для демонстрации создается dump базы, перед передачей или хранением нужно проверить, что в нем нет:

- реальных ФИО пациентов;
- диагнозов и медицинских сведений;
- токенов, паролей и ключей;
- production URL с учетными данными.

Дампы не должны попадать в Git. Для промышленной эксплуатации потребуется отдельная политика резервного копирования, шифрования, сроков хранения и удаления.

## Логи

Логи используются только для технической диагностики. В них разрешены:

- идентификаторы заявок;
- типы событий;
- коды ролей и статусов;
- статус доставки уведомления;
- технические сообщения об ошибках без секретов.

В логах запрещены:

- текст заявки и комментариев;
- JWT;
- `MAX_BOT_TOKEN`;
- пароли;
- медицинские и персональные данные пациентов.
