# Матрица ролей и прав

## Роли

| Код | Роль | Назначение |
|---|---|---|
| `employee` | Сотрудник | Создает заявки, просматривает свои заявки, подтверждает выполнение и закрывает заявку. |
| `executor` | Исполнитель | Просматривает назначенные заявки, берет их в работу и отмечает выполнение. |
| `admin` | Администратор | Просматривает все заявки, назначает исполнителей, контролирует справочники через seed-данные или административные скрипты. |
| `manager` | Руководитель | Зафиксирован в модели доступа. Полноценный кабинет руководителя относится к демонстрационному плюсу. |

## Права MVP

| Действие | Сотрудник | Исполнитель | Администратор | Руководитель |
|---|---:|---:|---:|---:|
| Вход в систему | Да | Да | Да | Да |
| Просмотр своего профиля | Да | Да | Да | Да |
| Создание заявки | Да | Нет | Да | Нет |
| Просмотр своих заявок | Да | Нет | Да | Нет |
| Просмотр назначенных заявок | Нет | Да | Да | Нет |
| Просмотр всех заявок | Нет | Нет | Да | Нет |
| Назначение исполнителя | Нет | Нет | Да | Нет |
| Изменение статуса назначенной заявки | Нет | Да | Да | Нет |
| Закрытие выполненной заявки | Да | Нет | Да | Нет |
| Просмотр отчетов | Нет | Нет | Да | Демонстрационный плюс |
| Управление пользователями через UI/API | Нет | Нет | Демонстрационный плюс | Нет |

## Реализация в итерации 2

- Пароли хранятся в виде bcrypt-хешей.
- Backend выдает JWT access token с ограниченным сроком жизни.
- Закрытые endpoint требуют заголовок `Authorization: Bearer <token>`.
- Проверка ролей реализована через dependency `require_roles`.
- Seed-пользователи создаются миграцией `202604260002_users_roles_auth`.
