# Материалы для главы об архитектуре и DevOps

## Архитектурное решение

Прототип построен как трехзвенная веб-система: React frontend, FastAPI backend и PostgreSQL. Backend инкапсулирует бизнес-логику, ролевые проверки, жизненный цикл заявок, работу с уведомлениями и формирование отчетов. Frontend отвечает за пользовательский интерфейс, но не является источником правил доступа: все критичные ограничения повторно проверяются на backend.

Такое разделение позволяет независимо проверять API автоматическими тестами, повторяемо применять миграции БД и запускать систему в контейнерах.

## DevOps-модель

DevOps-модель проекта основана на коротких итерациях, автоматической проверке и контейнерной поставке. Каждый значимый этап дает проверяемый артефакт: миграцию, endpoint, тест, Docker-конфигурацию, workflow или документ.

Pipeline GitHub Actions выполняет:

- проверку Python-кода;
- применение Alembic-миграций;
- запуск backend-тестов;
- сборку frontend;
- сборку Docker-образов;
- запуск контейнеров;
- smoke-тест `/health`.

## Безопасность

В проекте применяются JWT, ролевой доступ, bcrypt-хеширование паролей и запрет медицинских данных пациентов. Реальные секреты не хранятся в репозитории, а mock-режим уведомлений позволяет демонстрировать интеграционный контур без внешних токенов.

Структурированные логи фиксируют технические события, но не включают тексты заявок, комментарии, токены и медицинские сведения.

## Проверка результата

Результат проверяется набором unit, API, integration, smoke и security-тестов. Трассируемость требований связывает пользовательские сценарии с endpoint, тестами и критериями приемки.

Для демонстрационного плюса добавлены SLA, отчеты, статистика и seed-данные, которые позволяют показать управленческую ценность системы без ручного наполнения базы.
