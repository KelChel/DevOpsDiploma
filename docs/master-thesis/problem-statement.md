# Постановка задачи и границы проекта

## Постановка задачи

Необходимо разработать прототип веб-системы внутренних заявок медицинской организации и описать DevOps-модель ее непрерывной поставки.

Прототип должен показывать полный обязательный сценарий MVP: создание заявки сотрудником, назначение исполнителя администратором, обработку заявки исполнителем, закрытие заявки заявителем, фиксацию истории, комментарии и mock-уведомления.

## Цель

Повысить управляемость внутренних обращений за счет единого жизненного цикла заявки, ролевого доступа, прозрачной истории действий и повторяемого процесса поставки.

## Объект и предмет

Объект: процесс обработки внутренних заявок в медицинской организации.

Предмет: проектирование и DevOps-сопровождение прототипа веб-системы внутренних заявок.

## Границы проекта

Система является учебным прототипом. Она не является медицинской информационной системой, не хранит медицинские данные пациентов и не используется для реального оказания медицинской помощи.

Полноценный кабинет руководителя, отчеты, статистика, SLA и расширенная OpenAPI-документация относятся к демонстрационному плюсу и не блокируют приемку обязательного MVP.

## Выбранный стек

- Python FastAPI для backend;
- React для frontend;
- PostgreSQL для хранения данных;
- Alembic для миграций;
- JWT для авторизации;
- pytest и HTTPX для тестирования;
- Docker и Docker Compose для локального запуска;
- GitHub Actions для CI/CD.
